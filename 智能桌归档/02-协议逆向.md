### ⚠️ 这个 FX2 分析仪单段只能吐 0.5–1.5 秒

报 `Device only sent N samples`。采样率越低拿到的时长越长：500 kSa/s → 0.48 s，200 kSa/s → 1.55 s。
所以长时观察只能"连续短抓 + 自动筛选"，别指望一次抓 40 秒。

```bash
CLI="$HOME/.workbuddy/tools/sigrok-cli/sigrok-cli.exe"
"$CLI" -d fx2lafw --config samplerate=200k --samples 400000 -C D0,D2,D3,D4,D7 -o out.sr
python captures/analyze.py out.sr
python captures/frames.py out.sr
```

PulseView 里则设 1 MHz / 20 M 采样（约 20 s），解码器 UART、TX=D2、9600 8n1、极性 normal、idle high。

### 没有解码器时怎么定波特率

量突发内**最窄的脉冲宽度** T（起始位一定是最窄那档）：

| T | 波特率 |
|---|---|
| ≈ 104 µs | 9600 |
| ≈ 52 µs | 19200 |
| ≈ 8.7 µs | 115200 |

本机实测 102 µs → 9600。✔

## 2. 帧格式

```
我们发（→ 控制盒）:  F1 F1 │ CMD │ LEN │ PARAMS[LEN] │ CHK │ 7E
盒子回（→ 外设）  :  F2 F2 │ CMD │ LEN │ PARAMS[LEN] │ CHK │ 7E

CHK = (CMD + LEN + ΣPARAMS) & 0xFF
```

### 三个必须记住的坑

| 坑 | 说明 |
|---|---|
| **CHK 不含地址字节** | 只对 `CMD+LEN+PARAMS` 求和。把 `F1 F1` 算进去 → 命令被静默丢弃，现象和"命令不支持"完全一样 |
| **`0x7E` 不转义** | 高度 1150 mm 编码成 `04 7E`。靠"扫到 0x7E 就断帧"的解析器会在特定高度**周期性丢帧**，而且换个高度就好 |
| **整帧一次写入** | 分几次 `write_array()` 会让盒子收到半帧并静默丢弃 |

正确解析：**先读 LEN 算帧长（`6+LEN` 字节），再验 CHK**，不扫终止符。

## 4. 上报帧（← 控制盒）

| CMD | 含义 | LEN | PARAMS |
|---|---|---|---|
| `01` | 高度 | 3 | `[hi, lo, status]`，高度 = `(hi<<8)+lo`，**单位 mm** |
| `07` | 行程范围 | 4 | — |
| `20` | 限位标志 | 1 | bit0=上限已设，bit4=下限已设（本机 `0x11`） |
| `21` | 软上限 | 2 | 大端 mm（本机 1130） |
| `22` | 软下限 | 2 | 大端 mm（本机 850） |
| `25`–`28` | 记忆 1–4 | 2 | 大端 mm |

**`01` 的第三个字节**实测恒为 `0F`，社区在其他桌上是 `07`，含义未知，**忽略即可**。

## 5. 通信时序（决定固件怎么写）

| 观察 | 结论 |
|---|---|
| 静止时连续采 20 段（约 60 s）**零帧** | **不能只被动监听**，需要主动轮询——但见下面的"移动中禁止轮询" |
| 动作中以 **229 ms（≈4.4 Hz）** 连续上报 | 运动期间完全可以被动收，不必轮询 |
| 动作停止后还会持续几秒，然后彻底安静 | 停稳后补一次读即可 |
| 一次完整轮询 41 字节，首字节延迟 7.6 ms，全部到齐 129 ms | 轮询周期**不要小于 200 ms**，否则缓冲堆积（纯传输只需 43 ms，其余是帧间停顿） |
| 运动中发 `07` | **会打断自驱运动**，表现为每 400 ms 只走 10 mm |
| 刚停稳立刻发运动命令 | 偶发被忽略，等 300–500 ms 或靠抑制窗口覆盖 |

## 6. 实测高度轨迹（回归基准）

```
上升（软起加速 → 减速停住，末速约 13 mm/s）
1110 → 1116 → 1120 → 1123 → 1129

下降（匀速约 35 mm/s，符合捷昌 38 mm/s 标称）
1054 → 1046 → 1039 →（换向）→ 979 → 959
892 → 885 → 877 → 870 → 864 → 851
```

30 帧中 29 帧严格单调、方向正确、落在 851–1129 内。唯一不自洽的一帧判为编码器重新同步。

### 原始帧样本（可直接当单元测试）

```
# 上升段
F2 F2 01 03 04 56 0F 6E 7E   1110 mm
F2 F2 01 03 04 5C 0F 74 7E   1116 mm
F2 F2 01 03 04 60 0F 78 7E   1120 mm
F2 F2 01 03 04 63 0F 7B 7E   1123 mm
F2 F2 01 03 04 69 0F 81 7E   1129 mm   ← CHK 恰好等于 0x7E，解析陷阱实例

# 下降段
F2 F2 01 03 03 7C 0F 92 7E    892 mm
F2 F2 01 03 03 75 0F 8B 7E    885 mm
F2 F2 01 03 03 6D 0F 83 7E    877 mm
F2 F2 01 03 03 66 0F 7C 7E    870 mm
F2 F2 01 03 03 60 0F 76 7E    864 mm
F2 F2 01 03 03 53 0F 69 7E    851 mm
```

验算：`CHK = (01 + 03 + P0 + P1 + 0F) & 0xFF`，例如 `01+03+04+56+0F = 0x6E` ✓

| 项目 | 值 | 来源 CMD |
|---|---|---|
| 软下限 | **850 mm**（人为设定） | `22` |
| 软上限 | **1130 mm**（人为设定） | `21` |
| 限位标志 | `0x11`（上下限均已设） | `20` |
| 记忆 1/2/3/4 | **851 / 943 / 1037 / 1129 mm** | `25`–`28` |
| 单位 | `0` = 厘米（高度仍按 mm 上报） | `0E` |
| 速度档 | `0x23` = 35 | `13` |
| 防撞灵敏度 | `01` = 高 | `1D` |
| 运动模式 | `00` = 单触 | `19` |
| 低功耗 | `01` = 开 | `18` |
| 童锁 | `00` = 未锁 | `1F` |
| 固件版本 | `0A`（10） | `1C` |

### 两条重要推论

1. **软限位到不了。** 命令走到 850 时实际停在 **851**，顶端停在 **1129**——机械/编码器底位就是
   851。做场景判断必须留 **±2 mm 容差**，否则"是否到位"永远判 false。
2. **记忆位已被重写。** 出厂时 1/2/3 是 636–638 mm 的空值（低于软下限，永远够不到），
   现在四段按行程等分设好，可以直接当动作原语用。

## 8. 记忆位只能"走过去再存"

协议里**没有**"把第 n 位设成 X mm"这种命令，`B0` 那类带参数的写法在本机无效（写完读回不变）。
唯一可行路径：

```
1. F1 F1 1B 02 <hi> <lo> <cs> 7E     # 走到目标高度
2. 等它自己停稳（不要轮询！0x07 会打断自驱运动）
3. F1 F1 03 00 03 7E                 # 03/04/25/26 = 存为第 1/2/3/4 位
4. F1 F1 07 00 07 7E                 # 读回 25-28 校验
```

现成脚本：`tools/desk-presets.ps1 -Action apply`（按当前软限位四等分重写四位）。

## 9. 为什么不用社区组件

Rocka84 的 `jiecang_desk_controller` 是给 **HS 口**写的，分帧逻辑是"扫到 `0x7E` 就断帧"。
F 口 `0x7E` 不转义，用它会在特定高度周期性丢帧，且症状极具迷惑性——**换个高度就好了**。

所以固件只做一件事：**按 LEN 算帧长，再验 CHK**。见 `03-系统架构与固件设计.md`。
