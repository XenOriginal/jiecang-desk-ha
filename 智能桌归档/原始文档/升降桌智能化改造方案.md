# 升降桌智能化改造方案

> 对象：JCHT35K9 手控器 + JCB36NE3A-230 控制盒（捷昌 Jiecang）  
> 已有条件：Home Assistant、逻辑分析仪、ESP32-C3 Mini  
> 定位：不换电机、不换控制盒、不破坏原厂线束，在 HS 口"并联"一个数字手控器

---

## 一、现状盘点

### 手控器 JCHT35K9（官方 datasheet 已确认）

| 项目      | 参数                                                         |
| ------- | ---------------------------------------------------------- |
| 按键      | ▲ / ▼ / 记忆 1-4 / M（设置）                                     |
| 显示      | 3 位 7 段 LED，cm 或 inch 可选，闲置约 10 s 熄屏                       |
| 附加      | USB 充电口（注意：这是**输出**，不是供电入口）                                |
| 线缆      | 2000 mm，**8 pin 水晶头（RJ45/8P8C）**                           |
| 官方兼容控制盒 | JCB35N1/N2/N3/N4、JCB35M、JCB35NS1/NS2、JCB35MH3，及对应 JCB36 系列 |

结论：这是**数字手控器**，不是单纯的按键开关盒。它内部有 MCU，负责读按键、驱动 4 条按键线、接收并显示控制盒发来的高度数据。

### 控制盒 JCB36NE3A-230

- JCB36N 系列：500 W 级输出、待机 0.1 W、软起停、防撞回退、多通道（N3 = 3 通道）。
- `E` 后缀在捷昌的命名里通常对应**带第三方/物联网通讯口**的版本（GoBright 座席系统文档中出现的 JCB36NE2AP、JCB36N2CA 就是走这个口做外部控制）。
- `-230` 应为 230 V 交流输入版本（国内 220 V 可直接用）。
- **重要**：高度闭环（霍尔/编码器）和 4 组记忆**都在控制盒里**，不依赖手控器。这意味着我们只要冒充"手控器"，就能白嫖它成熟的软起停、防撞、限位和记忆功能。

### 上机前必须先做的端口盘点（拍照记录）

盒子侧面/底部丝印一般会出现这几个口，逐个确认：

| 丝印           | 含义          | 本次改造用途                    |
| ------------ | ----------- | ------------------------- |
| AC           | 220 V 输入    | 不碰                        |
| M1 / M2（/M3） | 电机          | 不碰                        |
| **HS**       | 手控器口（RJ45）  | 主接入点之一（与手控器并联）           |
| **RJ11 6P6C** | 大概率是 `F`/`BT` 扩展口（官方蓝牙模组 JCP35N-BLT 插这里） | **首选接入点**（独立全双工口，不碰手控器） |
| F / IOT / BT | 蓝牙或第三方通讯模块口 | 同上；若 RJ11 即此口，见 3.5 节       |

## 二、三条可行路线

|         | A. 并联数字手控器（ESP32 接 HS 口）      | B. 物理按键注入（拆手控器焊点）     | C. 官方 F/IoT 口 + 官方模块 |
| ------- | ----------------------------- | ----------------------- | -------------------- |
| 做法      | 用 RJ45 一分二把 ESP32 与手控器并到同一条总线 | 在手控器 PCB 上并接光耦/模拟开关跨接按键 | 插官方蓝牙/第三方 dongle     |
| 能拿到高度   | ✅ 原生 mm 级                     | ❌ 除非另加测距                | ✅ App 内可见            |
| 能任意高度定位 | ✅（发目标高度帧）                     | ❌ 只能按住上升/下降             | 部分                   |
| 保留原手控器  | ✅ 完全保留                        | ✅ 保留但被动过焊               | ✅                    |
| 工作量     | 中（需验证引脚）                      | 低                       | 低                    |
| HA 集成   | ✅ ESPHome 原生                  | ✅ 需自己写                  | ❌ 需逆向 BLE/云，基本封闭     |
| 风险      | 接错 5 V 会烧 IO                  | 焊接损伤面板                  | 生态锁定                 |

**推荐 A，B 作为 A 失败时的兜底，C 仅在你只想用手机 App、不接 HA 时考虑。**

> **补充路线 A′（更优，前提是盒上有 RJ11 的 F/BT 口）**：直接接那个 RJ11 口，占用的正是官方蓝牙模组的位置。它与手控器总线**物理隔离**，不需要一分二、不存在总线争用、手控器完全不受影响；而且是**全双工**，能力（读限位、读设置、读错误码）比 HS 口的手控器协议更完整。详见 3.5 节。**有 RJ11 口就优先走 A′，HS 口留作兜底。**

## 三、HS 口协议（社区已逆向，需自验）

数据来源：IPSW1/desk-control（恰好就是 JCB35N2 + JCHT35K9 这套组合）、phord/Jarvis、Rocka84/esphome_components、pmalecka/Jarvis。**均为第三方逆向，非官方文档，不同批次固件可能有差异。**

### 3.1 引脚定义（8P8C，5 V 逻辑，低电平有效）

| Pin | 功能                         | 说明           |
| --- | -------------------------- | ------------ |
| 1   | M 键                        | 拉低 = 设置键     |
| 2   | **高度输出 UART**              | 控制盒 → 手控器，单向 |
| 3   | GND                        |              |
| 4   | **控制盒 UART 输入**（原文档记为 "?"） | 我们的发送线接这里    |
| 5   | VCC +5 V                   | 手控器供电        |
| 6   | 记忆键公共线                     | 组合用          |
| 7   | 上升 + 记忆组合                  | 单独拉低 = 持续上升  |
| 8   | 下降 + 记忆组合                  | 单独拉低 = 持续下降  |

### 3.2 记忆位触发组合（拉低为 x）

| 记忆位 | Pin 6 | Pin 7 | Pin 8 |
| --- | ----- | ----- | ----- |
| 1   |       | x     | x     |
| 2   | x     |       |       |
| 3   | x     |       | x     |
| 4   | x     | x     |       |

存位：先拉低 Pin 1（M），再按对应组合。

> ⚠️ Pin 7 单独 = 上升，Pin 8 单独 = 下降，但 7+8 同时 = 去 1 号位。组合时序和持续时间必须实测（建议 100-200 ms 脉冲，两线同时拉低再同时释放）。

### 3.3 高度数据帧

- 9600 baud，8N1，5 V TTL，单向。
- **只在按键动作后**才开始发，持续约 10 s，间隔 15 ms。
- 帧格式：`0xF2 0xF2 [命令] [参数个数] [参数…] [校验和] 0x7E`，校验和 = 命令 + 个数 + 所有参数之和。
- 高度命令 `0x01`：`F2 F2 01 02 HH LL CS 7E`，高度 = `(HH<<8)+LL`，**单位 mm**（1093 → 109.3 cm）。

### 3.4 可发送命令（控制盒 ← 我们）

帧格式 `F1 F1 [命令] [个数] [参数…] [校验和] 0x7E`：

| 命令                        | 功能                       |
| ------------------------- | ------------------------ |
| 0x01 / 0x02               | 上升 / 下降一个步进（约 14 mm）     |
| 0x2B                      | 停止（**同时是唤醒帧**）           |
| 0x05 / 0x06 / 0x27 / 0x28 | 去记忆位 1 / 2 / 3 / 4       |
| 0x03 / 0x04 / 0x25 / 0x26 | 保存当前高度到记忆位 1 / 2 / 3 / 4 |
| 0x1B                      | **去指定高度**（2 个参数，单位 mm）   |
| 0x07                      | 请求物理行程上下限                |
| 0x20                      | 请求当前限位设置                 |
| 0x0C                      | 请求其他设置                   |

经验：距上一条消息超过 5 s 时，先发一次 `0x2B` 唤醒，再发正式命令。

### 3.5 RJ11 口（F / BT 扩展口）——优先考虑

> **状态：已在本机实测确认（2026-11-09 22:05）。** 该口输出标准捷昌帧，高度字段已解出并经桌子实动验证。以下是实测结果，不是推测。

它是捷昌给官方蓝牙模组 JCP35N-BLT 预留的插槽，本质是一个"外设总线"，我们只是顶替那个蓝牙模组坐进去。

#### 实测结论（本机 JCB36NE3A-230 + JCHT35K9）

用 8 通道逻辑分析仪按 `2-GND / 1-CH0 / 3-CH2 / 4-CH3 / 5-CH4 / 6-CH7` 接入，200 kSa/s 采样：

| Pin | 静态电平 | 判读 |
|---|---|---|
| 1 | 高 | NC + 内部上拉 ✓ |
| 2 | — | GND（基准） |
| 3 | 高（UART 空闲） | **盒 → 你 TX，实测有帧** ✓ |
| 4 | **高（5 V 常电）** | **给模组供电，确认是 F 口** ✓ |
| 5 | 高 | RX（你 → 盒），全程无反向驱动 ✓ |
| 6 | **低** | **第二根 GND**（旧文档记在 pin5 是数错位了） |

所以实际定义是：**`1 NC / 2 GND / 3 TX / 4 VCC+5V / 5 RX / 6 GND`**，与 Rocka84 新版一致。老文档把 GND 记在 pin5 是笔误，实测 pin5 是信号脚、pin6 才是地。

#### 协议（实测帧）

- **UART**：9600 8N1，5 V 逻辑。
- **帧格式**：`F2 F2 │ CMD │ LEN │ PARAMS[LEN] │ CHK │ 7E`，其中 `CHK = (CMD + LEN + ΣPARAMS) & 0xFF`。我们发出时地址用 `F1 F1`，盒子回复用 `F2 F2`。
- **高度上报 `CMD=01`，LEN=3**，`PARAMS[0..1]` 为大端高度，**单位 mm**（显示单位是厘米时）；`PARAMS[2]` 实测恒为 `0F`，社区在其他桌上是 `07`，**含义未知，忽略即可**。

实测原始帧（同一段 0.48 s 内两帧，间隔 229 ms）：

```
F2 F2 01 03 04 64 0F 7B 7E   → 高度 0x0464 = 1124 mm
F2 F2 01 03 04 67 0F 7E 7E   → 高度 0x0467 = 1127 mm
```

第二帧的校验和恰好是 `0x7E`，与帧尾同值——**这不是异常，是真实数据**（见下面的解析陷阱）。

实测高度轨迹（按▲上升 / 按▼下降期间抓取，共 30 帧）：

| 片段 | 高度序列 (mm) | 判读 |
|---|---|---|
| 上升 | 1110 → 1116 → 1120 → 1123 → 1129 | 软起加速后减速停住，末速约 13 mm/s |
| 下降 | 1054 → 1046 → 1039 →（换向）→ 979 → 959 | 匀速段约 35 mm/s，符合捷昌 38 mm/s 标称 |
| 下降 | 892 → 885 → 877 → 870 → 864 → 851 | 逐帧单调递减，每帧 6-8 mm |

30 帧中 29 帧严格单调、方向正确、数值落在 851-1129 mm 的真实行程内，因此**高度字段可以确定**。唯一一帧（860 出现在 892 之前）与相邻帧不自洽，判断为编码器重新同步，不影响结论。

#### 关键行为：静止时不说话

- 动作期间以 **~4.4 Hz（229 ms 间隔）** 连续上报。
- 动作停止后还会持续几秒，然后彻底安静。**实测桌子静止时连续采了 20 段（约 60 s 覆盖）零帧。**
- 结论：**不能只被动监听，必须主动轮询。** 这也正是 HS 口方案的短板，而 F 口能补上——它是全双工。

#### 可发送的命令（✅ 已在 USB-TTL 上逐条实测）

> **校验和只对 `CMD + LEN + PARAMS` 求和，不含 `F1 F1` 两个地址字节。** 这点极易写错——我第一版把地址也算进去了，结果五条命令全部被盒子静默丢弃，表现和"命令不支持"完全一样。排查时先验校验和。

| 功能 | CMD | 参数 | 帧示例 | 本机实测 |
|---|---|---|---|---|
| 请求设置（回 `25 26 27 28` + `01` 高度） | `07` | 0 | `F1 F1 07 00 07 7E` | ✅ **返回 41 字节，5 条帧** |
| 升一步 | `01` | 0 | `F1 F1 01 00 01 7E` | ✅ **+12 mm 后自停** |
| 降一步 | `02` | 0 | `F1 F1 02 00 02 7E` | ✅ **−10 mm 后自停** |
| 去记忆 1 / 2 / 3 / 4 | `05` / `06` / `27` / `28` | 0 | `F1 F1 27 00 27 7E` | ✅ 四位全部到位，误差 ≤1 mm |
| **直接去指定高度** | `1B` | 2（大端 mm） | `F1 F1 1B 02 03 DE FE 7E`（→990） | ✅ **3/3 命中，误差 ≤1 mm** |
| **急停** | `2B` | 0 | `F1 F1 2B 00 2B 7E` | ✅ 生效 |
| 请求软限位 | `20` | 0 | `F1 F1 20 00 20 7E` | ✅ 回 `20/21/22` 三条 |
| 童锁（读） | `1F` | 1（0 读 / 1 翻转） | `F1 F1 1F 01 00 20 7E` | ✅ 回 `00`=未锁 |
| 固件版本 | `1C` | 0 | `F1 F1 1C 00 1C 7E` | ✅ 回 `0A` |
| 读整个设置块 | `FE` | 0 | `F1 F1 FE 00 FE 7E` | ✅ 回 18 条设置 |
| **存记忆位（存当前高度）** | `03` / `04` / `25` / `26` | 0 | `F1 F1 03 00 03 7E` | ✅ **四位全部写入成功**（见 3.6） |
| 唤醒 / 轮询 | `29` | 0 | `F1 F1 29 00 29 7E` | ❌ **无任何应答** |
| 请求行程范围 | `0C` | 0 | `F1 F1 0C 00 0C 7E` | ❌ **无应答**（改由 `20`+`21`+`22` 拿） |
| 写记忆位（任意高度） | `B0` | 3（位号+大端0.1mm） | — | ❌ **无效**，写完读回仍是原值 |

> **记忆位不能直接写数值。** `B0` 这类"带参数的写记忆"在本机无效，协议里也没有对应的写命令。唯一可行的路径是：**先 `1B` 走到目标高度 → 停稳 → 发 `03/04/25/26` 把当前高度存成第 n 位**。详见下面的 3.6。

**实测中踩到的两个时序坑（写固件必须处理）：**

1. **PC 上打开串口后的第一帧会丢。** 这发生在端口刚 `Open()` 之后，是 CH340/Windows 驱动层的现象。**2026-11-10 用 ESP32-C3 直连实测没有这个问题**，第一次发 `07` 就完整收到 41 字节。所以固件里的重发只是保险，不是必需。
2. **刚停稳就立刻发下一条运动命令，偶发被忽略。** 一次 `GOTO 900` 在紧接 `LOWER` 之后发出，完全没有反应；同样协议在间隔稍长后 100% 生效。所以**每条运动命令后要等 300-500 ms，并且用高度反馈确认是否真的动了，没动就重发一次**。

**定点精度实测**：目标 1000 → 999、目标 860 → 860、目标 930 → 929，三次全部到位，误差 ≤1 mm，移动 70-150 mm 耗时 3-6 s。

#### ⚠️ 解析陷阱：0x7E 不转义

`0x7E` 是帧尾，但**它不会被转义，而且会出现在载荷里**。高度 115.0 cm 编码为 `04 7E`，此时若解析器靠"扫到 7E 就断帧"，**停在 115 cm 的桌子就永远读不到高度**。

正确做法：**先读 LEN 算出帧长，再校验 CHK**，不要扫终止符。本机第一帧就撞上了这个坑（校验和正好 0x7E），所以这条不是理论风险。

#### 本机配置快照（读回的真实值，固件可按此校验）

| 项目 | 值 | 来源 |
|---|---|---|
| 当前高度 | 851–929 mm（测试过程中变动） | `01` |
| 软下限 | **850 mm**（人为设定） | `22` |
| 软上限 | **1130 mm**（人为设定） | `21` |
| 限位标志 | `0x11`（上下限均已设） | `20` |
| 可用行程 | **850–1130 mm（28 cm）**，机械实际可停 851–1129 | 21/22 |
| 记忆 1 / 2 / 3 / 4 | **851 / 943 / 1037 / 1129 mm**（已按行程四等分写入） | `25–28` |
| 单位 | `0` = 厘米（高度按 mm 上报） | `0E` |
| 速度档 | `0x23` = 35 | `13` |
| 防撞灵敏度 | `01` = 高 | `1D` |

**两条重要推论：**

1. **软下限 850 mm 到不了。** 命令走到 850 时实际停在 **851 mm**，即机械/编码器底位就是 851。同理顶端停在 1129。**做场景判断时不要把 850/1130 当精确值，用 ±2 mm 容差。**
2. **记忆位已被重新写入。** 出厂时 1/2/3 是 636–638 mm 的空值（低于软下限，永远够不到），现在四段已按行程等分设好，可以直接用 `05/06/27/28` 当动作原语。

#### 3.6 记忆位的写法（记忆位不能直接写数值）

协议里**没有**"把第 n 位设成 X mm"这种命令，`B0` 那类带参数的写法在本机也无效（写完读回不变）。唯一可行路径是四步：

```
1. F1 F1 1B 02 <hi> <lo> <cs> 7E     # 走到目标高度
2. 等它自己停稳（不轮询！0x07 会打断自驱运动）
3. F1 F1 03 00 03 7E                 # 03/04/25/26 = 存为第 1/2/3/4 位
4. F1 F1 07 00 07 7E                 # 读回 25-28 校验
```

两个实测细节：

- **会有 1 mm 的系统性欠走**（减速停）。想让某位精确落在 X，指令里就发 `X+1`；两端撞软限位的位则无法补偿，只能接受 851/1129。
- **存完立刻读会读空**，中间要留 ~900 ms。PC 端刚 `Open()` 后的第一帧也会丢（驱动层现象，MCU 直连不存在），读之前先空发一次 `07` 预热。

本机已按此写入，实测到位精度：

| 记忆位 | 存储值 | MOVE 实测到位 | 误差 |
|---|---|---|---|
| 1（坐，行程底） | 851 mm | 851 mm | 0 |
| 2（1/3） | 943 mm | 944 mm | +1 |
| 3（2/3） | 1037 mm | 1037 mm | 0 |
| 4（站，行程顶） | 1129 mm | 1129 mm | −1 |

脚本：`tools/desk-presets.ps1`（`-Action check / apply / verify / test`，`-Only n` 单独处理某一位）。

#### 相比 HS 口的优势

| | RJ11 / F 口 | HS 口（并联手控器） |
|---|---|---|
| 是否动原手控器 | ❌ 完全不动，物理隔离 | ⚠️ 需一分二并联 |
| 总线争用 | 无 | 需确认 pin4 未被手控器占用 |
| 全双工 | ✅ 可主动查询，随时取高度 | 只在按键后广播 10 s |
| 命令集 | ✅ 完整（限位、设置、错误码，phord/pmalecka 逆向的就是这条链路） | 手控器子集 |
| 供电余量 | ❌ 只够喂 BLE 模组（几十 mA），**不能给 ESP32 供电** | 同上，余量未知 |
| 风险 | 低（唯一风险是引脚接错） | 中（并联 + 时序 + 记忆线误触发） |

#### ESP32 接法

`pin2 → GND`，`pin3 → GPIO(RX，经 10 k/20 k 分压)`，`pin5 → GPIO(TX，经 100 Ω 直连；实测 3.3 V 逻辑)`，`pin4 悬空不接`，`pin1 悬空`。UART 参数不变：**9600 8N1**。

> ⚠️ **实测 pin5 = 3.3 V，可以 100 Ω 直连**（2026-11-10 测；接 ESP32 前拔掉 CH340 再复测一次，见 `ESP32-C3接入计划.md` 3.2）。若复测为 5 V，必须改用非反相电平转换——**绝不能用单管开漏**：它是反相电路，UART 空闲高电平会被按成低电平，盒子永远收不到有效帧。

**双向已经验证完毕**（2026-11-09，USB-TTL）：pin5 上的帧被盒子正常接受，`1B` 定点误差 ≤1 mm，`05/06/27/28` 记忆位可用，`2B` 急停生效。唯一没做的是把 USB-TTL 换成 ESP32——这一步现在有完整的落地方案，见 **`ESP32-C3接入计划.md`**。

#### 局限与退路

- 部分固件会对该口上的"陌生设备"保持沉默，需要先发唤醒帧 `F1 F1 29 00 29 7E`（`29` 就是官方定义的 WAKE）再试。
- dongle 口**不发送** `LIMIT_STOP(23)` 和 `REP_PRESET(92)` 两条上报，所以"到限位了"和"正在去预设位"这两件事不能靠这个口直接得知，得靠高度曲线自己推断（高度停止变化 = 到位或停住）。
- 若这个口对发送完全不应答，**退回 HS 口并联方案**，能力略降但不影响主线功能。
- 顺带一提：直接买官方 JCP35N-BLT 插上也能用官方 App，但那就进不了 HA（要逆向 BLE 私有协议），不如 ESP32 划算。

## 四、推荐整体方案

```
【首选：走 RJ11 的 F/BT 口】
ESP32-C3 Mini ── RJ11(6P6C) ── F/BT 口 ┐
                                       ├── 控制盒 JCB36NE3A-230 ── M1/M2 ── 桌腿
手控器 JCHT35K9 ── RJ45 ── HS 口 ──────┘        │
      └── Wi-Fi ── Home Assistant ── 语音 / 手机 / HomeKit / 传感器 / 日历

【退路：RJ11 不应答时，走 HS 口并联】
手控器 JCHT35K9 ──┐
                  ├── RJ45 一分二 ── HS 口 ── 控制盒 ── 桌腿
ESP32-C3 Mini ────┘
```

两条路共用同一套固件与 HA 配置，区别只在接线：**先试 RJ11，不通再并 HS 口**。

### 分层能力（按稳妥程度递进，建议按此顺序上线）

| 层级      | 能力                      | 风险  | 说明                 |
| ------- | ----------------------- | --- | ------------------ |
| L1 只读   | 实时高度、升降状态、久坐计时          | ≈0  | 只接 Pin 2 + GND，纯监听 |
| L2 记忆位  | 一键坐/站（走盒内 4 组记忆）        | 极低  | 盒子保证软起停、到点停、防撞     |

## 五、电路与接线要点

1. **ESP32-C3 不耐 5 V。** 两套接法只是引脚号不同，电路逻辑一样：
   - **发送线**（HS 口 pin4 / RJ11 口 pin5）：本机实测 pin5 = 3.3 V，**只需 `GPIO → 100 Ω → pin5`**，再并一只 BAT54S 钳位（1 脚接 GND、2 脚接信号、3 脚接 3V3），防复位/未供电那段高阻期被 5 V 顶。
   - 若复测确认是 5 V 电平，改用 **BSS138 非反相电平转换**（栅极接 3V3，源极接 GPIO 并 10 k 上拉到 3V3，漏极接信号线并 10 k 上拉到 5 V）。
   - ❌ 任何情况下都**不要用单管开漏**（GPIO → 1 kΩ → 2N7002 栅极，源极接地，漏极接线）。那是**反相**电路：UART 空闲高电平，GPIO 空闲高 → MOS 导通 → 线被按在低电平（break），盒子永远收不到有效帧，现象和"协议不支持"完全一样，极难自查。
   - **接收线**（HS 口 pin2 / RJ11 口 pin3）：5 V 经 10 k/20 k 分压到 3.3 V 再进 GPIO（或 1 kΩ 串联 + BAT54S 钳位）。
   - **电源脚**（HS 口 pin5 / RJ11 口 pin4）：**不接**，仅用来测量确认。GND 必须接。
2. **上电毛刺是头号事故源。** 有案例：ESP32 上电瞬间某脚默认拉低，桌子自己往下降了两秒。所以：
   - 直连方案靠 100 Ω 限流 + BAT54S 钳位兜底；若改用电平转换，BSS138 天然安全（栅极固定偏置，GPIO 悬空不导通）；若用开漏则栅极必须 100 kΩ 下拉；
   - **挑"无系统职责"的脚**：ESP32-C3 Super Mini 上只有 **IO0 / IO1 / IO3 / IO10** 完全干净；IO2/IO8/IO9 是 strapping（IO8 复位需为高、IO9 是 BOOT），IO4-IO7 带 bootstrapping / JTAG / Quad-SPI flash 职责；
   - **串口优先用 IO20 / IO21**（UART0 专用，丝印就是 RX/TX），代价是日志要改走 USB-Serial-JTAG；
   - GPIO18/19 是 USB D±，GPIO11-17 未引出（GPIO11 是 VDD_SPI），都不要碰。
3. **供电必须独立。** HS 口的 5 V 是给手控器用的，余量未知；ESP32 Wi-Fi 发射峰值会把它拉塌，进而干扰手控器甚至让盒子复位。用桌下独立 5 V 适配器，**只共 GND**。
   - 顺带好处：控制盒待机时可能切断自身 5 V 轨，独立供电能保证 ESP32 不掉线。
   - 如果桌下没有插座，先测 HS 口 5 V 能带多少电流再决定。
4. **UART 争用。** 手控器在这套组合里只"听"高度、只驱动按键线，理论上不占用 Pin 4。但仍需用逻辑分析仪确认 Pin 4 在手控器操作时是否被拉低；若被占用，ESP32 的 TX 串 1 kΩ 限流，并只在总线空闲时发送。
5. **线序方向别搞反。** RJ45 引脚号以"铜针朝上、卡扣朝下、从左到右 1-8"计。不同批次 Pin 2/Pin 4 可能互换，**VCC 位置也可能不同**——把 5 V 接到 3.3 V IO 上会直接烧芯片。
6. **不要碰 AC 和电机线。** 断电后再动线；盒子内部有高压。
7. **可还原。** 全程用一分二和免焊接线端子，不剪原厂手控器线；拆前拍照，保修期内尤其注意。

## 六、固件（ESPHome）

> **不要直接用 Rocka84 的 `jiecang_desk_controller` 组件走 F 口。** 它的分帧是"扫到 `0x7E` 就当帧尾"，而本机实测第一帧的校验和就是 `0x7E`（`… 0F 7E 7E`），桌子停在 1127 mm、1150 mm 这些高度时会周期性丢帧。走 HS 口时它没问题，走 F 口必须按 LEN 分帧。

### 6.1 F 口配置（完整版已独立成文件）

可直接编译的完整配置在 **`esphome/desk-c3.yaml`**（+ `esphome/desk_proto.h`），配线、引脚选择和每个坑的处理见 **`ESP32-C3接入计划.md`**。这里只保留设计要点，避免两份配置各自漂移。

**三条关键设计：**

1. **引脚**：`IO20`(RX) ← pin3（10 k/20 k 分压），`IO21`(TX) → pin5（100 Ω 直连，实测 3.3 V），`IO0/IO1/IO3/IO10` 全部空着。日志改走 `USB_SERIAL_JTAG`，因为 UART0 被协议占用了。
2. **分帧**：按 `LEN` 算帧长，再校验 `CHK`，**绝不扫 `0x7E`**。
3. **轮询**：静止 1.5 s 后发 `07` 取高度；**运动期间禁止轮询**（`07` 会打断自驱运动）。用"最近一次运动命令"的时间戳压住 3 s 窗口。

轮询判据大致是这样：

```cpp
const uint32_t now = millis();
if (now - last_rx > 1500 && now - last_poll > 700 && now - last_move_cmd > 3000) {
  desk::simple(id(desk_uart), desk::CMD_SETTINGS);
  last_poll = now;
}
```

发送只有几行（记住校验和只算 `CMD+LEN+PARAMS`，不含 `F1 F1`）：

```cpp
std::vector<uint8_t> f = {0xF1, 0xF1};
uint8_t cs = 0;
for (auto b : payload) { f.push_back(b); cs += b; }
f.push_back(cs);
f.push_back(0x7E);
uart->write_array(f.data(), f.size());
```

解析侧的状态机短这样（`buf` 是 `std::vector<uint8_t>` 累积缓冲）：

```cpp
while (buf.size() >= 4) {
  if (buf[0] != 0xF2 || buf[1] != 0xF2) { buf.erase(buf.begin()); continue; }
  const size_t len = buf[3];
  const size_t total = 6 + len;          // F2 F2 CMD LEN ... CHK 7E
  if (buf.size() < total) break;         // 还没收全，等下一批
  uint8_t cs = 0;
  for (size_t k = 2; k < 4 + len; k++) cs += buf[k];
  if (cs != buf[total-2] || buf[total-1] != 0x7E) { buf.erase(buf.begin()); continue; }
  // 到这里才是可信帧：cmd = buf[2]，payload = &buf[4]
  buf.erase(buf.begin(), buf.begin() + total);
}
```

## 九、兼容性与实施注意事项（重点）

1. **协议是逆向的，不是官方文档。** 本机是 `E` 变体（带通讯口）+ `-230`，官方兼容列表里没有这个精确型号。所有命令都要实测确认，尤其是 `0x1B`。
2. **断电后高度可能失准。** 记忆位存的是编码器相对值，断电期间若被外力转动/皮带打滑，会偏移。建议每次上电后先降到最低点回零，或加 VL53L1X 做交叉校验。
3. **长按式移动是危险模式。** 若用 `0x1B` 走到限位或做连续上升，必须带：高度反馈 + 超时（≤30 s）+ 无位移即停 + HA 侧全局急停。绝不要用社区里那个"关掉防撞"的 kill mode。
4. **先设限位再自动化。** 在盒子里设好最小/最大高度、锁定、防撞灵敏度调高，再做自动化。否则一次误触发就能撞坏显示器。
5. **上电时序。** ESP32 重启/OTA 期间 IO 会瞬变，务必保证此时所有按键线为高阻。物理上用栅极下拉保证，软件上避免在 `on_boot` 里动按键线。
6. **单点故障（仅并联方案）。** 一分二接触不良 → 手控器失灵。用带卡扣的成品分线器，线缆做应力释放，别吊着。
7. ~~RJ11 的 pin5 有歧义~~ **已实测解决**：pin5 是 RX（静态高、无反向驱动），**pin6 才是第二根 GND**（静态低）。旧文档把 GND 记在 pin5 是数错了一位。
8. **RJ11 的 5 V 只够喂 BLE 模组。** 官方 JCP35N-BLT 功耗是几十 mA 级，ESP32 Wi-Fi 峰值几百 mA，从 pin4 取电会欠压复位，甚至把盒子拉进异常。
9. ~~RJ11 口可能是手控器口而不是扩展口~~ **已实测排除**：pin4 有 5 V 常电、且插着它时手控器在 HS 口工作正常，确认是独立的 F 扩展口。
10. **手控器 USB 口不是电源入口。** 那是充电输出，且可能随熄屏断电，别拿来给 ESP32 供电。
11. **供电共地但不要共 5 V。** 两路电源只共 GND，避免倒灌。
12. **逻辑分析仪接 5 V 信号**：克隆 Saleae 一般耐 5 V，但先确认；不确定就加分压。
13. **保修。** 转接板 + 免焊接线端子的方案基本可无损还原，但仍建议拆前拍照、保留原线。
14. **儿童/宠物。** 加"移动前 TTS 播报"，并把物理急停（拔手控器或关插座）留在手边。
15. **别指望手控器屏幕常亮。** 它 10 s 熄屏是硬件行为，改不了；需要常显就自己做一块 OLED 挂在 ESP32 上。
16. **`0x7E` 不转义，会出现在载荷与校验和里。** 本机实测第二帧就是 `… 0F 7E 7E`。任何"扫到 7E 就断帧"的实现都会在特定高度上稳定丢帧，且症状极具迷惑性（换个高度就好了）。**必须按 LEN 分帧 + 校验 CHK。**
17. **静止时无数据，必须轮询。** 靠被动监听会得到一个永远停在"最后一次动完的高度"的实体。**用 `07`，不要用 `29`**（`29` 在本机实测完全静默）。
18. **dongle 口少两条上报。** `LIMIT_STOP(23)`、`REP_PRESET(92)` 不会从这个口发出，所以"到限位了""正在去预设位"得靠高度曲线推断（高度不再变化即为到位）。
19. **校验和别把 `F1 F1` 算进去。** 只算 `CMD+LEN+PARAMS`。算错的后果是**盒子完全静默，和"命令不支持"一模一样**，极难自查。实测踩过。
20. **PC 端口打开后第一帧会丢，刚停稳立刻发命令偶发被忽略。** MCU 直连实测无首帧丢失（2026-11-10），但"停稳后发命令"仍要留 300-500 ms 并用高度反馈确认。
21. **记忆位不会跟着限位变。** 改过软上下限后，`25–28` 里存的仍是旧高度，得重跑一次 `tools/desk-presets.ps1 -Action apply` 重新四等分。出厂时 1/2/3 是 636–638 mm 的空值（低于软下限所以永远够不到），不要拿它当"未设置"以外的语义。
22. **端点有 1 mm 死区。** 软下限 850 实际停在 851、软上限 1130 停在 1129，做场景判断要留 ±2 mm 容差，否则"是否已到位"会永远判 false。

## 十、结论

**全部验证完成。RJ11 口双向都通，这是最终方案，HS 口并联彻底不需要了。**

本机实测确认的全链路：

| 环节 | 状态 |
|---|---|
| 物理层 | `2-GND / 3-TX / 4-VCC+5V / 5-RX / 6-GND`，9600 8N1 ✅ |
| 协议 | `F2 F2 CMD LEN … CHK 7E`，CHK 只算 CMD+LEN+PARAMS ✅ |
| 读高度 | `07` 轮询，**延迟 15-16 ms**，返回 4 条记忆 + 1 条高度 ✅ |
| 步进 | `01`/`02`，**每步约 10-12 mm 且自动停** ✅ |
| **定点** | `1B`，**3/3 命中，误差 ≤1 mm**，70-150 mm 移动耗时 3-6 s ✅ |
| 急停 | `2B` ✅ |
| 配置回读 | 软限位 850/1130、速度 35、灵敏度高、单触模式、未锁 ✅ |

- 复用控制盒已有的闭环、软起停、防撞和限位，安全边界不变；
- 手控器完全不受影响，物理隔离，接 ESP32 的物料约 45 元；
- 能力上可以做到"任意高度 + 一键坐站 + 久坐提醒 + 语音 + HomeKit + 全屋联动"，和原厂万元级智能桌的功能集基本齐平；
- 全程不剪线、不碰强电、可还原。

### A.2 软件设置（PulseView / sigrok）

- 采样率 **1 MHz**，采样深度 20 M（约 20 s）；要精确量位宽时改 4 MHz / 4 s。

### A.4 判读决策树

| 现象 | 结论 | 下一步 |
|---|---|---|
| D2 动作时出现 `F2 F2 …` 突发，D3 恒高 | F 口确认，且同步广播状态 | 最理想，直接进 Step 1 只读 |
| D2 静默、其余脚全静止，D3 恒高 | 口有电但盒子不主动说话 | 用 ESP32 发 `F1 F1 2B 00 2B 7E` 唤醒后重抓 |
| D3 静态**低**（无 5 V） | 该口待机断电，或引脚映射不同 | 让屏幕保持点亮再测；逐脚重排 |
| 六脚全静止且 D3 低 | 可能是手控器口且待机断电，或插头没到位 | 检查卡扣深度，换根 6P6C 线 |
| D4 有数据而 D2 没有 | pin3 / pin5 功能互换 | 按实测改接，RX 换到 D4 |
| D0 或 D7 有电平变化 | "NC" 其实带功能 | 记录，可能是第二路 UART 或检测脚 |

### A.9 安全提醒

- 分析仪的 GND **只接 pin2**，不要再接别的地，避免地环路。
- CH3 接的是 5 V 常电，虽是高阻输入，但别让那根线蹭到相邻脚。
- **抓包阶段不要同时接 ESP32**，先把信号看清再上单片机。
- 逻辑分析仪与桌子共用 USB 地，跳线别超过 30 cm，抓 9600 这种低速信号不必担心线长，但接 5 V 常电的那根要短。
