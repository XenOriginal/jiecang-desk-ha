## 2026-11-09　从零到看清信号

| 时间 | 事件 | 结论 |
|---|---|---|
| 上午 | 盘点设备：JCHT35K9 + JCB36NE3A-230 | 控制盒是 `E` 后缀，带第三方通讯口；高度闭环和记忆都在盒子里 |
| 上午 | 对比三条路线（HS 并联 / 拆手控器焊键 / 官方 F 口） | **选 F 口**：物理隔离、全双工、不碰手控器 |
| 下午 | 逻辑分析仪接 RJ11，200 kSa/s 抓包 | 确认 `1 NC / 2 GND / 3 TX / 4 VCC+5V / 5 RX / 6 GND`，纠正社区旧文档的 pin5=GND 笔误 |
| 下午 | 测最窄脉宽 102 µs | 9600 baud 确认 |
| 晚上 | USB-TTL 逐条实测命令 | `07` / `01` / `02` / `05,06,27,28` / `1B` / `2B` / `20` / `1F` / `1C` / `FE` / `03,04,25,26` 全部可用 |
| 晚上 | 定点精度测试 | 目标 1000→999、860→860、930→929，**误差 ≤1 mm** |
| 深夜 | 写 `tools/desk.ps1` | PC 上先能控桌子，把协议彻底跑熟再上单片机 |

**关键发现**：`0x7E` 不转义且在载荷里出现（第一帧的 CHK 就恰好是 `0x7E`）。
这一条后来决定了整个固件的分帧逻辑。

## 2026-11-11 ~ 11-12　挂灯可行性调研（已挂起）

用户提出：能否在现有模块上加 `lamperez/xiaomi-lightbar-nrf24` 的功能，控制桌上的米家挂灯
MJGJD01YL。

**调研结论：必须额外加一颗 nRF24L01+，无法用 ESP32-C3 自带的射频替代。**

| 依据 | 说明 |
|---|---|
| 挂灯不是蓝牙设备 | 接收芯片是 **Telink TLSR8368**（无线鼠标键盘那一类私有 2.4G） |
| 帧格式私有 | `8B 前导(53 39 14 DD 1C 49 34 12) │ 3B 遥控ID │ FF │ 2B 指令 │ 1B 计数 │ CRC16`，CRC16 = poly `0x1021` / init `0xFFFE` / 非反转 |
| 调制 | 2 Mbps GFSK，跳频，至少 3 个 2 MHz 信道 |
| 单向 | 遥控只发、灯条只收，**没有握手**；配对 = 断电重启后 20 s 内发一帧让它改认新 ID |
| BLE 为何不行 | 只有 2402/2426/2480 三个固定广播信道；前导/访问地址/CRC24 由**硬件生成**，协议栈只让填 payload；LE 2M 仍是 BLE 帧 |
| nRF24 为何可行 | 关掉硬件 CRC 和 ACK 后就是个裸 FSK 调制器：5 字节地址可当同步序列、payload 任意、信道任意、2 Mbps GFSK，与 Telink 同族 |

**成本**：nRF24L01+ 裸板约 10 元（**不要**买 PA+LNA 版，近距离反而过载）。
不需要第二块 MCU——现有 C3 引脚够用（CE4 / CSN10 / SCK6 / MOSI7 / MISO5，与 UART20/21 无冲突）。
合并版配置已实际编译通过（flash 52.3% / RAM 33.2%）。

**为什么挂起**（而不是直接做）：

1. 该组件对 nRF24 是**高频轮询**，会给 ESPHome 主循环带来持续 SPI 负载，
   可能推迟"静默后首帧"那套精确时序；
2. 2.4G 与 Wi-Fi 抢频（默认 channel 68 = 2468 MHz，靠近 Wi-Fi 13）；
3. 桌面控制已经稳定，不值得为了一个灯冒回归风险。

**待定选项**：A 合并到现有 C3 ／ B 另加一块 C3 做独立灯条节点 ／ C 不动硬件。
（倾向 B：桌面固件零风险，可独立刷写调试。）

> ⚠️ 若哪天要做，注意上游例程用的是 IO4/5/6/7/10，与 `01-硬件接口.md` §6 "避开 IO4–IO7"
> 的谨慎结论冲突。这几个脚在 C3 上确实可复用为 SPI，但上电瞬间的 strapping 电平要实测。

## 被否掉的路线（别重走）

| 路线 | 否掉的原因 |
|---|---|
| 拆手控器焊光耦/模拟开关 | 焊接损伤面板，且只能"按住上升/下降"，无法定点 |
| 官方蓝牙 dongle + App | 需逆向 BLE/云，基本封闭，无法进 HA |
| 走米家当自动化触发 | 跨品牌 Matter 设备在米家通常只是只读执行端 |
| 引用 Rocka84 的 `jiecang_desk_controller` | 是 HS 口组件，"扫 `0x7E` 断帧"，在 F 口会周期性丢帧 |
| 900 ms 轮询保数据实时 | 手控器屏幕永不熄灭（这是用户直接反馈的问题） |
| 单管开漏做电平转换 | 反相，UART 空闲高会把线按在 break 状态，现象与"协议不支持"一样 |
| `number.set_value` 直接触发运动 | HA 对相同状态去重，连说两次"坐下"第二次无效且无报错 |
| cover 设 `device_class: shutter` | 前端整套文案变"窗帘"，按钮提示对不上桌子 |
