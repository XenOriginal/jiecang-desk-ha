# 智能书桌改造 · 项目归档

> 对象：捷昌 JCHT35K9 手控器 + JCB36NE3A-230 控制盒
> 接入方式：RJ11「F/BT」扩展口 → ESP32-C3 Super Mini → ESPHome → Home Assistant
> 归档时间：2026-11-12　状态：**已上线，日常在用**

---

## 一句话讲清做了什么

不换电机、不换控制盒、不拆手控器。在控制盒那个原本插蓝牙模组的 RJ11 口上，并联一个
ESP32-C3 冒充"官方 dongle"，用逆向出来的 9600 baud 私有协议读高度、发指令。
桌子自己成熟的高度闭环、软起停、防撞、四组记忆全部白嫖，原手控器一行线都没动。

**三层分工**（这是整套设计最重要的约束）：

```
ESP32-C3 固件       →      Home Assistant      →      HomeKit / 语音 / 前端
只做协议翻译              只做语义和逻辑               只管嘴
只管读帧、发帧             mm↔%、坐站、计时、场景         Siri / 家庭 App / 卡片
```

固件里没有业务判断，HA 里没有协议细节。任何一层挂掉，另外两层和桌子本身照常工作。

## 硬件一览

| 件 | 型号 | 备注 |
|---|---|---|
| 手控器 | JCHT35K9 | 8P8C 数字手控器，3 位 LED，闲置约 10 s 熄屏 |
| 控制盒 | JCB36NE3A-230 | 500 W 级，软起停 + 防撞 + 4 记忆，固件版本 `0A` |
| 主控 | ESP32-C3 Super Mini | 4 MB flash / 400 KB SRAM，陶瓷天线偏弱 |
| 接口 | RJ11 6P6C 转接板 | 插在控制盒`F/BT`口（原蓝牙模组位） |

改造 BOM 约 **12 元**：100 Ω ×1、BAT54S ×1、10 k/20 k 各 1、100 µF + 100 nF 各 1、
洞洞板外壳。**不需要** BSS138 电平转换（实测 3.3 V 逻辑）。

| 项 | 值 |
|---|---|
| 串口 | 9600 8N1，`GPIO20`=RX ← 盒 TX，`GPIO21`=TX → 盒 RX |

## 五分钟上手

```bash
# 1) 编译固件（不要用 Git Bash，见 03 文档「编译环境」）
python -m esphome compile esphome/desk-c3.yaml

# 2) 部署 HA 侧（宿主机上）
scp homeassistant/desk.yaml root@YOUR_HA_HOST:/Lager/data/homeassistant/packages/
scp homeassistant/www/desk-vertical-slider.js root@YOUR_HA_HOST:/Lager/data/homeassistant/www/
docker exec homeassistant python -m homeassistant --script check_config -c /config
docker restart homeassistant

# 3) 不接 ESP32 也能验证协议（USB-TTL 直连 RJ11）
powershell -ExecutionPolicy Bypass -File tools/desk.ps1 -Cmd status
```

## 三条不可忘的原则

1. **手控器永远保留。** 它是物理独立的另一路，ESP32 死机、HA 重启都不影响桌子。
   出任何问题，拔掉我们的板子就回到原厂状态。
2. **移动中不要轮询。** `0x07` 会打断自驱运动，表现是"每 400 ms 只走 10 mm"，
   极易误判成电机没劲。
3. **`0x7E` 不转义。** 任何"扫到 7E 就断帧"的解析器都会在特定高度周期性丢帧，
   而且换个高度就好——这是最难查的一类 bug。必须按 `LEN` 算帧长再验 `CHK`。
