# 05 · 运维与故障对照

---

## 1. 一分钟自检（怀疑出问题时先跑这个）

```bash
# 不经过 ESP32，直接用 USB-TTL 问控制盒（最可靠的基准）
powershell -ExecutionPolicy Bypass -File tools/desk.ps1 -Cmd status
```

正常输出：

```
Height      : 921 mm
Memory 1    : 851 mm
Memory 4    : 1129 mm
Limit flags : 0x11
Soft max    : 1130 mm
Soft min    : 850 mm
```

- 这一条通 → 桌子和协议没问题，问题在 ESP32 / 网络 / HA。
- 这一条不通 → 先查接线与电平（`01-硬件接口.md` §4），别动软件。

**静默自检**：在 HA 里盯 `sensor.desk_rx_frames`，**空闲 20 秒数字必须不动**。
一动就说明有东西在发帧，手控器屏幕会被唤醒。

## 2. 故障对照表

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 实体一直 `unavailable` | 分压接反 / 没共地 | 量 IO20 空闲是否 3.3 V；确认 pin2 与 USB 电源 GND 相通 |
| 有应答但高度不更新 | 运动中仍在发 `0x07` | 看日志；确认抑制窗口生效，别改回轮询 |
| 发命令完全没反应 | 两个 TX 打架 / 极性接反 | 确认 CH340 TX 已拔；量 pin5 空闲是否 5 V（是则必须用**非反相** BSS138） |
| 换某些高度就丢帧 | 用了"扫 `0x7E` 断帧"的实现 | 必须按 `LEN` 分帧再验 `CHK`（当前固件已做） |
| 到 851 / 1129 就停 | 软限位 + 1 mm 死区，**不是故障** | 自动化留 ±2 mm 容差 |
| `cover.desk` 状态不跟随 | 实体 id 对不上 | 用 `desk.yaml` 头部的对照表核对真实 id |
| 连续两条命令，第二条无效 | 命令落在"刚停稳"死区 | 脚本里加 `delay: 1s`；`script.desk_goto` 已串行化 |
| 桌子以"每 400 ms 走 10 mm"龟速移动 | 运动中发了 `0x07` | 立刻停手，等它走完；检查抑制逻辑 |
| 定点过冲几十毫米 | 静默后首帧被收成残帧 | 必须走 `primed_goto()`（含热身帧 + 幂等重发） |
| 单步走两步的距离 | `primed_simple` 被重发了 | 单步**绝不重发**，重发 = 行程翻倍 |
| Wi-Fi 频繁掉线 / Auth Failed | 满功率发射 + 陶瓷天线 + 桌下金属 | `output_power: 8.5dB`、`power_save_mode: light`；移出金属横梁；焊 31 mm 漆包线 |
| 手控器屏幕常亮 | 有周期性流量在唤醒它 | 看 `Rx Frames`；检查是否有人加回了轮询 |
| 改软限位后记忆位不对 | 记忆位不跟随限位 | 重跑 `desk-presets.ps1 -Action apply` |

## 3. 换了控制盒 / 改了固件版本怎么办

本机是 `0A`。换盒子后**不要假设命令集一样**：

1. `desk.ps1 -Cmd status` → 看固件版本（`1C`）和四个记忆位；
2. 逐条试 `1B`（定点）、`2B`（急停）、`20`（限位）；
3. 复核真实端点（可能不是 851/1129）→ 改 `substitutions.desk_min/desk_max`；
4. 重跑 `desk-presets.ps1 -Action apply` 重写四位。

## 4. 风险清单（按踩坑概率排序）

1. **天线是这块板最弱的一环。** 桌下金属多、电机干扰大，掉线优先怀疑这里，别先怀疑协议。
2. **`0x7E` 不转义。** 任何"扫终止符"的实现都会在特定高度丢帧，且换个高度就好——极难查。
3. **移动时不要轮询。** 会变成"每 400 ms 走 10 mm"的龟速，很容易误判成电机没劲。
4. **IO4–IO7 有 flash 职责。** 别因为"网上都这么接"就换过去，踩中就是"上电不启动"。
5. **IO8 复位必须为高。** 拿它点灯会让板子偶尔进不了下载模式。
6. **哪天改回 5 V 逻辑，别用单管开漏。** 那是反相电路，现象是"完全没反应"，跟协议不通一模一样。
7. **两个 TX 不能并在一起。** 接 ESP32 前必须断开 CH340 的 TX。
8. **端点有 1 mm 死区。** 850 实际停 851、1130 停 1129，自动化留 ±2 mm 容差。
9. **记忆位不跟随限位。** 改了软上下限要重跑 `desk-presets.ps1 -Action apply`。
10. **别指望米家能当自动化触发条件。** 跨品牌 Matter 设备在米家通常是只读执行端。
11. **ESP32 掉了不影响用桌子。** 手控器永远优先且物理独立。
12. **改设备名前必须备份注册表。** 否则 `entity_id` 重算会把所有模板打断。

## 5. 还原路径

**最快**：拔掉 RJ11 插头 + 拔掉 USB 供电 → 桌子回到原厂状态。
手控器从未被改动，插回原蓝牙模组位也不影响任何东西。

**软还原**：`script.desk_goto` 设为 `mode: single` 且永远走夹取，不会把桌子顶到硬限位；
`desk_runaway_stop` 自动化在连续运动 90 s 时强制急停，兜住协议异常。

---

## 6. 日常要固化下来的三件事

1. `esphome/` 与 `homeassistant/` 进 git（`secrets.yaml` 不入库）；
2. 记下控制盒固件版本（`0A`）与实测端点（851 / 1129），换盒子或改限位时先复核；
3. 手控器永远保留 —— 这是"改坏了也能还原"的底气。

## 7. 归档维护

改完固件或 HA 配置后，跑一次：

```bash
bash 智能桌归档/工具/刷新快照.sh
```

它会重抓源码快照、重算 SHA-256 并刷新 `MANIFEST.md`，同时提示哪些文件与上次快照不同。
